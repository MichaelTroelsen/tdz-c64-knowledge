## Figure OCR - 2026-07-31

- ~~**Rasterize pages instead of (only) extracting embedded images**~~ — **DONE** (2026-07-31). `extract_document_figures` found figures only via `page.get_images(full=True)` (embedded raster XObjects), so vector-drawn schematics, memory maps and timing diagrams produced nothing. `TDZ_FIGURE_RASTERIZE_PAGES=1` now also renders each page's drawing regions via `page.cluster_drawings()` at `TDZ_FIGURE_RASTER_DPI` (200) and OCRs those (`server.py`, `_extract_vector_figures`). Deliberately **not** a full-page render — that would OCR the body text a second time on top of what the PDF's text layer already indexed. Clusters over `TDZ_FIGURE_RASTER_MAX_AREA` (0.9) of the page are borders and are skipped; clusters that sit on top of an already-extracted embedded image are skipped via `page.get_image_rects()` overlap. Verified against the live corpus: `Schematic_U36_adapter.pdf` has 0 embedded images and 1 vector cluster (the whole schematic), `goat_tracker_commands.pdf` 0 embedded and 11 clusters. Off by default — it is much more expensive per page.

Note this parallelises *within* a document; the extraction worker itself is still one thread processing one job at a time, which is fine now that the expensive part is pooled.

## HTTP Transport - Cross-Machine Verification - 2026-08-21

- **Cross-machine HTTP-transport verification (issue #16) remains untested** - Only loopback (`127.0.0.1`/`localhost`) binding of the streamable-HTTP transport has been exercised; a real non-loopback client-to-server run across two machines has not been performed, and this cycle **deliberately declined to attempt it** rather than start a server and bind a port without a credential on hand. **Decision:** loopback testing is accepted as sufficient for now; issue #16 stays closed against this untested non-loopback path. **What a future attempt needs**, both gates enforced by `server.py`'s `_run_http`/`_transport_security_settings`: (1) `server.py:492-500` - binding to a non-loopback `host` with no `api_keys` raises `SystemExit` unless `TDZ_MCP_ALLOW_INSECURE=1` is set (this transport exposes `add_document` and `scrape_url`, i.e. arbitrary-URL fetch from the host - SSRF - to the network with no auth); the real fix is setting `TDZ_API_KEYS` rather than the insecure override. (2) `server.py:450-457` - with no `TDZ_MCP_ALLOWED_HOSTS` configured and `host` not in `_LOOPBACK_HOSTS`, DNS-rebinding protection is left **disabled** (a warning is logged, not an error) because the `Host` header the remote client will send is not knowable in advance; `TDZ_MCP_ALLOWED_HOSTS` must name the client's hostname to turn it back on. No credential was requested or supplied this cycle, and neither variable was set. **Files:** `server.py` (`_run_http`, `_transport_security_settings`).
