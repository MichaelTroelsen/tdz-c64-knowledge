# TO-DOS

## MCP Expansion Caveats (deferred from reliability audit) - 2026-07-26 08:36

- **Add polite-crawl defaults before scraping volunteer wikis** - Harden `scrape_url` before bulk-scraping small volunteer-run wikis (cpcwiki, beebwiki, amigadev) for the Amiga/CPC/BBC platform expansion. **Problem:** No robots.txt handling, no User-Agent header, no retry/backoff, and defaults to 10 threads at 100ms delay - a real risk of getting rate-limited or IP-banned from small sites. `max_pages` is accepted as a parameter but is explicitly unimplemented (a code comment confirms mdscrape doesn't support it yet), so any page cap passed in is silently ignored. **Files:** `server.py` (scrape_url monitor/config, and the `max_pages` comment near the mdscrape command-line construction). **Solution:** Lower default thread count and raise delay, implement a real `max_pages` enforcement (client-side cap since mdscrape doesn't do it), add an identifying User-Agent, and check robots.txt before crawling a new domain.

- **Build a SID-archive ingestion path for HVSC / DeepSID** - Needed before the SID-music expansion can actually reach these two sources. **Problem:** There is no `.sid`/`.psid`/`.rsid` file parser and no `.zip`/`.lha` archive handling anywhere in the ingestion pipeline, so HVSC (a `.sid` file archive) can't be ingested at all. DeepSID is a JS single-page app driving a JSON API rather than static HTML, so the existing markdown-based scraper would only capture navigation chrome, not music metadata. **Files:** `server.py` (`_extract_text_for_file` dispatch - no `.sid`/`.zip` branch exists). **Solution:** At minimum, add a PSID/RSID header parser that turns a `.sid` file's metadata (title, author, released, chip model) into an ingestible text card; archive support (`.zip`/`.lha`) would let that run directly against HVSC's own distribution format. DeepSID likely needs its JSON API queried directly rather than scraped as HTML.
